# Patterns

This folder contains recurring product UI situations that require careful thinking during design and implementation.

The goal of this folder is not to define high-level principles, but to focus on the practical UI patterns, states, and interaction situations that repeatedly affect product quality in real work.

## Rules

Before adding a new file, answer these questions:

1. Does it describe a recurring UI situation that appears in real product work?
2. Does it help make better decisions in a specific implementation context?
3. Is it concrete enough to go beyond general advice?
4. Does it focus on situations where product UI can succeed or fail in practice?
5. Would this still be useful across different products, not just one isolated screen?

## What does not belong here

This folder is not for:

- high-level philosophy
- general advice without a specific scenario
- large collections of links
- broad learning materials
- reusable checklists or review templates

## Reminder

Patterns explain where product UI usually succeeds or fails in practice.

They should help turn abstract quality into concrete implementation thinking.
